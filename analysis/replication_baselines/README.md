## Three caveats that must appear in the write-up

**1. Their released CSVs have 0.1s timestamp resolution.** Only 32% of stamps are distinct, with up
to 27 events sharing one, against ~95% distinct (microsecond) in our runs. This systematically
inflates their `log_inter_arrival` distance. It is an artifact of the released file format, not a
property of their model. **Every mean quoted above excludes inter-arrival**; the all-six mean is
given in the table for completeness but should not be the headline.

**2. Their released timestamps needed reconstruction.** The files carry `MM:SS.s` with the hour
component lost. `evaluation/lob_bench/fix_released_timestamps.py` rebuilds absolute time by counting
minute wraps from a 09:45 anchor. Validation: the reconstruction yields a session of exactly
**09:45 → 11:00 (75.0 minutes)**, matching this project's existing 75-minute window convention, and
mid-price ranges that sit inside real's for both days. The anchor is an assumption, but a
well-supported one — state it.

**3. Windows are not identical across runs.** Theirs is 75 min from 09:45; our DDPM-100 is 60 min
from 09:30; our DDIM-1 is 120 min from 10:00. Each is scored against its **own** matching real
slice, which is the standard approach, but it means the comparison is between models each measured
against real — not a controlled head-to-head. Say so once.

## Two further observations about *their* released model

Both visible in `stylized_THEIRS_ddpm_INTC_0130.png`, and both are properties of the **published**
model rather than anything this project introduced — which makes them safe and useful to state:

1. **Their model is range-bound too.** Its mid-price stays within roughly 33.85–33.95 across the
   session while the real market declines from 34.0 to 33.4. It does not track the day's trend.
   This matters because the same criticism is later levelled at our models: it is a property of the
   architecture, not of the acceleration.
2. **Wrong sign on volume–volatility correlation**: theirs sits at about −0.03 where real is +0.41.

Stating these in §5.1 is not point-scoring — it establishes the baseline's characteristics honestly
before §5.2 diagnoses what acceleration adds on top.

## The finding worth making explicit

On 2015-01-29 our **DDIM-1 scores better than their working DDPM** (0.673 vs 0.855, excl.
inter-arrival) — despite that same run collapsing to \$31.86 against real's \$33.76 and never
recovering.

**LOB-Bench measures distributional fidelity, not price-path validity.** A run can reproduce
plausible spread, depth and imbalance distributions while the price trajectory is nonsense. This is
a genuine limitation of the benchmark, it is visible in your own data, and stating it:

- justifies why this project reports `uniq_mid`, `ret1s_std` and price-path diagnostics *alongside*
  LOB-Bench rather than relying on it alone;
- pre-empts the obvious challenge to §5.5, where LOB-Bench and return-volatility disagree about the
  scheduled-sampling model;
- is the reason the single-step failure needed a **two-hour** window to become visible at all — the
  collapse occurs at minute ~73, so a 30-minute evaluation would have missed it and the benchmark
  alone would never have flagged it.

## Note on the stylised-fact convention

All batteries here are computed on **1-minute bars with lags 1–30 minutes**, matching the TRADES
paper's own "Lag (minutes)" 0–30 axis, so the panels are directly comparable to their published
figures.

This was corrected on 2026-08-06. The earlier version used 1-second bars, which left lags 1–30
spanning only 1–30 *seconds*: on a 75–120 minute session that removes under 1% of the series, so the
correlation barely changed across lags and the panels rendered as flat lines (measured:
volume-volatility varied by 0.003 across all lags on the released TRADES output). At 1-minute bars
the same lag range covers a quarter to half the session and the structure is visible — real
volume-volatility now spans 0.81 where it previously spanned 0.02.

Caveat to state if pressed: a 75-minute session gives only ~75 one-minute bars, so lag-30
correlations rest on ~45 overlapping points and are noisy. That is inherent to the paper's own
convention on a session of this length, not a choice made here.

Override with `--resample 1s` (or any pandas offset) if a different convention is wanted.
